MVI News App with jetpack compose and Clean Architecture  Clean Architecture : In this approach , the code is divided into following layers. When we make any application it includes so many files and classes so to increase the readability , we use this : -------------------------
|      UI Layer         |
|-----------------------|
|   Presentation Layer  | ← ViewModels/Controllers , UI compostables , intent , state ,
|-----------------------|
|   Domain Layer        | ← UseCases, model classes,Entities (business logic) , interfaces and 						modules
|-----------------------|
|   Data Layer          | ← Repositories implementation , local DB
 |-----------------------|
|   Data Interpretatio         | ←App module , Network module
-------------------------   A. Splash Screen :

These are 2,3 pages where we can go from one page to another using “next” and “back” button . Whenever you reach to the last page , the “next button” on last onboarding page changes to “get started button” and clicking on which you will be migrated to the first screen on the app.  

We will implement this onboarding feature using MVI and for that we need a repo interface and its implementation , viewmodel and usecase class  , intent and stateOfUI class.  a. Add the following dependencies

Create a onboarding data model class : defined inside domain layer .it will represent the attributes of each onboarding page such as title, description and image . It is a “data” class because it does not have any behaviours to be defined and Kotlin’s data class automatically provides useful functions like equals(), hashCode(), toString(), and copy().   In the clean architecture we represent the model classes inside domain layers.  c. Create an onboarding Usecase class : defined inside domain layer . In Clean Architecture, use cases represent the business logic and act as an intermediary between the presentation (UI view model) and data layers ( repository). Use case always have an operator function named “invoke” which interact with the repository and fetch the data from repo and return that data to view model .  d. Create an onboarding repository interface and its implementation class :  defined interface in the domain layer and its implementation in the data layer package . It is used to interact within view model and use cases. It will have a function which will actually have the data . Like list of onboarding objects , 1 object for each page.  e. Create an OnboardingIntent class : define it in the presentation layer.there are only 3 intents possible on onboarding pages I.e. previous page , next page and finish. We will make a sealed class . Sealed class can have “data class “ type and “object” type . Declare it data class if data arguments are there otherwise object type.  f.
